# Аудит и изменения сервиса

Проверка выполнена 5 октября 2026 года по предоставленной локальной копии репозитория и материалу «Агростраховая премия.docx». Изменения сохранены в отдельной копии; исходная папка в Downloads и удалённый GitHub-репозиторий не изменены.

## Итог

Реализованы форма и API с водным балансом, тремя погодными рисками, выбором стоимости капитала, NPV и дисконтированной окупаемостью. Код разделён на модули и покрыт тестами. При этом исходные данные **не позволяют подтвердить научную пригодность нейросетевого прогноза**. Старые модели отключены. Подготовлены отдельные процессы обучения микроклимата и урожайности, которые не допускают неподтверждённый результат к расчёту.

## Выявленные ошибки

| Область | В исходной версии | Исправление |
|---|---|---|
| Подготовка ML-данных | Координаты, физиологические и технологические признаки создавались `np.random.uniform`; при отсутствии таблиц генерировались также цели | Только реальные значения; пропуски сохраняются; отдельный набор проверенных наблюдений |
| Микроклимат | Отдельной модели температуры/влажности/ET не было; все модели предсказывали `productivity_change` | Отдельный контракт для изменений температуры воздуха, почвы и ET; явный статус отсутствия модели |
| Качество нейросетей | В сохранённых отчётах crop R² = −1,737, forest R² = −291,033 | Отказ от этих артефактов; сравнение с baseline, независимый holdout, порог качества |
| Работа API | Загружались RF-модели; нейросетевой предиктор из другого файла фактически не использовался | Один слой загрузки и проверки артефактов, единый контракт train/predict |
| Проверка обучения | Масштабирование выполнялось до train/test split; варианты одного исследования могли попадать в обе части | Масштабирование внутри train/fold; разделение по публикациям и связанным study_id |
| Урожайность | 85% назывались «изменением»; результат обрезался в диапазон 50…150%; площадь/покрытие/высота не были признаками crop-модели | Однозначная относительная урожайность; геометрия входит в новый контракт; без произвольного обрезания прогнозов |
| Лесное хозяйство | Проценты относительного выхода из обучающей таблицы интерпретировались как м³/га | Явная базовая продуктивность в м³/га/год и сценарное отношение |
| Справочники | API читал `data/*.csv`, хотя файлы находились в корне; ошибки скрывались | Файлы в `data/`, абсолютные пути относительно пакета, проверка схемы и видимый статус |
| Цены рыбы/древесины | Совокупная стоимость производства/торговли в USD использовалась как цена единицы продукции в RUB | Неверная автоподстановка исключена; требуется ручная цена |
| Урожайность FAO | Бралась первая строка без проверки года и единиц; несколько названий культур не совпадали с таблицей | Последний доступный год, точное соответствие страны/культуры, явное преобразование единиц |
| NASA POWER | Смешивались месяцы двух лет и годовые агрегаты, каждый месяц считался как 365/12 дней; пропуски заменялись нулём | Один завершённый год, календарные месяцы, метаданные единиц, явный отказ при пропусках |
| Энергетика | Одновременно использовались мощность 445 Вт и несогласованный КПД 24%; даже при нулевой площади создавалась одна панель | Единая модель по DC-мощности, целое число панелей, нулевая выработка без панелей |
| Окупаемость | На возврат CAPEX относилась вся сельхозвыручка, существующая и без АВ | Только дополнительный денежный поток относительно базового хозяйства |
| Капитал | Стоимость капитала отсутствовала | Прямая ставка/WACC, NPV, IRR, дисконтированный поток и окупаемость |
| Загрузка проектов | Частичный успех скачивания мог незаметно перезаписать весь датасет | Проверка всех источников перед атомарным переключением снимка |
| Обслуживание | Несколько дублирующих сценариев обучения и маскирующие ошибки `except` | Единый конвейер, информативные ошибки, структурированные статусы, CI |

Отрицательный R² здесь означает, что конкретные сохранённые прогнозы хуже константы, равной среднему целевых значений на тесте. Новая проверка дополнительно сравнивает MAE с baseline, обученным только на train. Повторное обучение на тех же случайных признаках не устранило бы причину проблемы.

## Проверка источников

Точные URL и технические результаты сохранены в [source-check.json](source-check.json), настройки — в [sources.json](../data/sources.json). Все три Google Sheets действительно доступны и соответствуют назначениям:

| Источник | Статус | Строк в выгрузке |
|---|---|---:|
| Растениеводство | HTTP 200, CSV, ожидаемые поля | 112 |
| Лесное хозяйство | HTTP 200, CSV, ожидаемые поля | 32 |
| Аквакультура | HTTP 200, CSV, ожидаемые поля | 34 |

После отбора строк с указанной культурой/организмом: 106, 31 и 22 соответственно. Отличия отражают заполненность таблиц, а не потерю исходных строк; исходные 178 записей сохранены целиком.

Протокол загрузки теперь содержит хеши файлов и происхождение каждой строки. Это подтверждает получение данных **с этих URL**, но не научную корректность ручного переноса данных из статей в таблицы.

NASA POWER: официальная структура запроса проверена по [документации NASA](https://power.larc.nasa.gov/docs/services/api/temporal/monthly/). Прямые попытки получения данных через urllib/requests и проверка через веб-инструмент не завершились успешно; наблюдалась ошибка TLS EOF. Это не доказывает ошибочность URL или недоступность NASA для других пользователей. Интеграционные тесты формата выполнены на фикстурах, а не на живом ответе.

Шесть локальных справочников загружаются, но их upstream-происхождение не подтверждено. Нет URL конкретной выгрузки, даты получения и контрольной суммы, зафиксированной при исходном скачивании. У цен культур нет года. Устранять этот пробел подстановкой произвольной ссылки на главную страницу FAO/Росстата было бы неправильно.

## Почему пока нет достоверного ML-прогноза

Отчёт извлечения: [preparation_report.json](../dataset/preparation_report.json).

- Изменение температуры воздуха: 3 заполненных числовых значения.
- Изменение температуры почвы: 3.
- Снижение ET: 2.
- Все три цели микроклимата одновременно: 2 строки, ещё без полного набора условий.
- Относительная урожайность: 94 значения.
- Урожайность + покрытие + высота одновременно: 9 строк, 6 уникальных значений DOI; разные культуры.

Проценты урожайности требуют ручной сверки с контролем. Климатические условия конкретного опыта, полив и тип системы не нормализованы. Заполнять их вымышленными значениями нельзя. Даже объединение разных культур не создаёт независимых наблюдений для прогноза пшеницы или томатов.

Подготовлены CSV-шаблоны и рабочий программный конвейер. Для включения реального прогноза нужны проверенные данные и успешная внешняя проверка. В версии 4 публичный расчёт использует средние по строкам и сценарную связь с геометрией; обучаемые модели остаются отдельным исследовательским конвейером. В тестах проверено успешное обучение на искусственно заданной зависимости, но это **тест реализации**, не оценка точности агрономии.

## Работа с приложенным документом

Разделены вероятность события и тяжесть потери. В публичной оптимизации рассматривается фиксированная система; трекеры требуют отдельной геометрической модели. Коэффициенты снижения ET, температуры, вероятности и страховой премии из документа не зашиты как универсальные установленные факты. Доход от электроэнергии не уменьшает физический ущерб урожаю и не даёт автоматической скидки страховщика.

## Изменения версии 4

Добавлены NSGA-II по трём целям (продуктивность, энергия, NPV), явный пользовательский выбор и девять погодных/экономических сценариев. Геометрия связана со светом, сценарным микроклиматом, биологическим откликом, энергией и стоимостью. Эта связь пока не калибрована по полевым данным; все коэффициенты и условная привязка средних описаны в [методике](METHODOLOGY_RU.md).

Публичный интерфейс и API показывают показатели вариантов, энергетика — только мощность и выработка. Конфигурации и происхождение коэффициентов сохраняются в закрытой SQLite. Программа `owner_console.py` запускается отдельно, требует пароль и не монтируется на публичный сайт. Диагностика «модель не обучена» убрана из пользовательского процесса; ограничения точности переданы понятным сообщением о предварительном расчёте.

FAO для культур используется как ориентир базовой урожайности страны; в рыбных/лесных файлах нет площади, поэтому продуктивность на гектар из национального объёма не вычисляется. Средние по видам берутся из числовых строк базы; рыба имеет абсолютный выход, его сравнение с базой не доказывает эффект АВ.

## Проверка результата

51 автоматический тест прошёл на Python 3.12. Проверены формулы, источники, валидация, исследовательский ML-конвейер, известный тестовый фронт NSGA-II, недоминируемость показанных вариантов, влияние геометрии, девять сценариев, отдельная авторизация владельца, сохранение выбора и отсутствие геометрии в публичном контракте. Ruff и синтаксис JavaScript проверяются перед поставкой. Тесты не подтверждают полевую точность.

Удалённый GitHub и развёртывание на Render не изменялись. Протокол финальных проверок — `verification.json`.

## Что требуется для полноценного внедрения

1. Сверить исходные наблюдения по статьям; уточнить определение урожайности относительно контроля, независимость опытов и реальные признаки.
2. Получить парные полевые измерения АВ/контроль для микроклимата и достаточные наблюдения по каждой культуре; дополнить сезонные климатические данные, полив, почву и сорт.
3. Получить точные источники и датированные выгрузки справочников цен/урожайности.
4. Проверить живой запрос NASA в среде размещения. При недоступности использовать явно введённые данные, а не скрытый fallback.
5. При наличии отдельного frontend-репозитория обновить его контракт: новые поля есть в этой поставке в API и встроенной форме `/calculator`.

Эти пункты относятся к данным, полевой валидации и развёртыванию; их нельзя считать выполненными только изменением кода.
